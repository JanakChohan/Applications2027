1The bottom line

What Rubrik actually does

Rubrik sells software that keeps protected spare copies of a large organisation's computer systems, checks those copies for signs of attack, and uses them to rebuild the organisation quickly after hackers strike.

It started with files and databases. It now also protects the login systems that control who can access what, and it supervises AI assistants so their mistakes can be reversed.

The 30-second version for a friend

"Big companies get hacked, and the hackers lock or wreck their systems. Rubrik keeps spare copies the hackers cannot touch, works out which copy is clean, and rebuilds the company from it. It now does the same for login systems and for AI assistants that go wrong."

Three things it protects

  • Data: servers, databases, files, cloud systems and online apps such as Microsoft 365.
  • Identity: the login systems that decide who is allowed into what. If these are down, nothing else can be fixed.
  • AI agents: AI assistants that take actions on a company's behalf. Rubrik watches them, limits them and can undo what they did.

Why it matters in one line

Attackers now delete a victim's backups before demanding money, so the victim has no way out but to pay. Rubrik's whole design starts from the assumption that the attacker is already inside.

2Full product and service breakdown

Rubrik sells software by subscription. Some customers also take storage hardware to hold copies on their own sites. Everything is grouped into two platforms.

First, how one protected copy is made

Every product below depends on this one process. It is worth understanding once, properly.

  • Step 1, Read. After the first full copy, Rubrik only collects what changed. The industry phrase is "incremental forever". It keeps each run small and fast.
  • Step 2, Seal. Data is squeezed to save space, scrambled so outsiders cannot read it (encrypted), and written to storage that only accepts additions.
  • Step 3, Inspect. Rubrik records a fingerprint of each file and a summary of what changed. This is the raw material for spotting attacks later.
  • Step 4, Restore. Rubrik can copy data back. It can also start a system running directly from the copy, which it calls Live Mount, so staff are working again before the full copy-back finishes.

The customer's rule is called an SLA Domain. It states the outcome wanted, such as "every four hours, keep one year, second copy abroad". There are no backup schedules to hand-build.

These are what separate Rubrik from an ordinary backup tool. Each one answers a specific attacker move.

A. Data Protection

What it is: the process above, applied wherever a customer's systems live.

  • Own buildings: virtual servers (VMware, Microsoft Hyper-V, Nutanix), databases (Oracle, Microsoft SQL Server, SAP), large shared file stores.
  • Rented cloud: Amazon Web Services, Microsoft Azure, Google Cloud. Google BigQuery was added in November 2026.
  • Online apps: Microsoft 365, Salesforce, Jira.
  • Code stores: GitHub and Azure DevOps.

Rubrik Cloud Vault is an optional extra copy held in an account that Rubrik owns and runs, with separate logins from the customer's. One fee covers storage and the cost of pulling data back out.

Why Rubrik sells it: it is the entry ticket. It is also the source of the history that every security product further down relies on.

B. Cyber Recovery and Threat Analytics

What it is: tools that inspect the copies and tell you which one is safe to restore.

Anomaly Detection: spotting an attack from the backups

  • After each backup, a small file describing what changed is sent to Rubrik's hosted service. Only that description travels, not the customer's actual files.
  • Check one compares the changes with that system's own normal pattern: how many files were added, deleted or altered.
  • Check two looks for a sharp rise in randomness in the files. Scrambled files look random, so this is a strong sign of ransomware. The technical word is "entropy".
Why this is clever, and where it is weak

It needs nothing extra installed on the machine being protected. So an attacker who switches off the security software on a server does not switch off this check.

A rival vendor argues that very slow, partial scrambling can stay under the alarm level. That is a competitor's claim, but worth knowing.

Threat Hunting and Turbo Threat Hunting

  • Threat Hunting searches the copies for known malicious files, using their fingerprints or pattern rules (called YARA rules).
  • Turbo Threat Hunting uses the fingerprints already recorded in Step 3, so it looks them up in an index. Rubrik's test figure is 75,000 backups in under a minute.
  • Results are written onto each backup's record. Infected ones can be quarantined so nobody restores one by mistake.

Rebuilding in the right order

  • Clean-room recovery: an isolated space to rebuild and test before reconnecting to the main network.
  • Preemptive Recovery Engine: works out the last clean copy before an incident, so the answer is ready on the day.
  • Autonomous Business Recovery: the customer tags one resource. Rubrik follows its connections to map the whole application, then restores network first, then computing, then data. The cloud version is in private preview.

Why Rubrik sells it: in a real attack, copying data back is rarely the slow part. Deciding which copy to trust is. This is the product that moves Rubrik from the IT budget to the security budget.

C. Data Security Posture Management (DSPM)

What it is: a map of where sensitive information sits and who can reach it.

  • It scans stored data and labels items such as card numbers, health records and passport details.
  • It shows which people and apps have access, and flags access that is wider than it should be.
  • The scanning runs inside the customer's own cloud account. Only the findings leave. The technology came from Laminar, bought in 2023.

Why Rubrik sells it: companies turning on AI helpers like Microsoft Copilot need to know what those helpers can read. After a break-in, it also answers "what did they get?"

D. Identity Resilience

What it is: backup and recovery for login systems. The three covered are Microsoft Active Directory (on a company's own servers), Microsoft Entra ID and Okta (both online).

Why it matters: the login system is the master key cabinet. If it is down, staff cannot sign in to anything, including the tools needed to recover.

Active Directory recovery

  • Forest recovery: a "forest" is a company's whole Active Directory. Rubrik rebuilds it through a five-step guided process. Rubrik says Microsoft's manual method is 29 steps across more than 100 pages.
  • Identity-First Recovery: it lifts only the directory database (a file named NTDS.dit) and its settings folder (SYSVOL) out of the backup. It places them on a freshly built Windows server.
  • That leaves behind anything the attacker hid in the old server's operating system.
  • By default it also removes the records of every other login server, so the rebuilt one does not try to sync with dead or infected machines.
  • Limit: the new server must run the same major version of Windows Server as the old one.

Entra ID and Okta recovery

  • Restores deleted or altered users, groups, apps and access rules straight into the live account.
  • Maps what depends on what. Restore a user, and the groups that user needs come back in the same step.
  • For Okta, it slows itself automatically to stay inside Okta's limits on how fast outside tools may make requests.
  • If a whole account is compromised, it can restore into a separate, clean account.

Roll Forward and Identity Continuity (both private preview)

Old-style recovery forces a trade. Go back three weeks and you are clean but have lost every new starter, leaver and password change. Stay put and the attacker's hidden accounts stay too.

Identity Roll Forward restores the clean copy, then replays only the legitimate changes and drops the attacker's.

Identity Continuity covers the gap while recovery runs. If the main login provider is down, it switches people to a standby. It comes from Strata, bought in June 2026.

Microsoft Defender link (March 2026): Microsoft's security tool flags a compromised account, and Rubrik reverses just that account's changes.

Why Rubrik sells it: most break-ins now start with a stolen or tricked login. No other system can be restored until logins work.

E. Rubrik Agent Cloud

An AI agent is an AI assistant that takes actions: it edits files, changes databases, sends messages. Agent Cloud, launched in October 2025, supervises agents built on other companies' AI.

  • Agent Observability (watch): a live list of every agent, what it can touch, and what it is doing.
  • Agent Identity (permit, August 2026): each action gets its own short-lived pass, valid for that one action. No agent holds a permanent key. It plugs into the Okta or Entra set-up a firm already has.
  • Agent Runtime Security (stop): a small AI model named SAGE judges the intent of each action before it runs, and blocks ones that break the rules.
  • Agent Rewind (undo, August 2025): records each agent's inputs, the tools it used and the chain of instructions behind an action. A bad change can be traced to its cause and reversed on its own.

For Anthropic's Claude Code (June 2026): Rubrik keeps unchangeable copies of code stores outside the store itself. It also tracks the files that steer the assistant, such as CLAUDE.md, settings and tool permissions, and flags unexpected changes.

"Fine-tuning for accuracy": the job advert uses this phrase. It refers to Predibase, bought in 2025, which trains small, specialised AI models on a company's own data so agents make fewer mistakes at lower cost.

Limit: an independent analyst notes Agent Rewind can only undo agents whose actions it is able to observe.

Why Rubrik sells it: "undo" is Rubrik's core skill, and agents are a new thing that needs undoing. It also opens the AI budget, which is far larger than the backup budget.

F. Rubrik AI and Annapurna

  • Rubrik AI (June 2026): the customer states a goal in plain words, such as "recover the payments system cleanly". The assistant plans and runs the steps across both platforms.
  • Annapurna: feeds a company's stored documents to its own AI tools, while keeping the rules on who may see what.

G. Services

  • Support and the Ransomware Response Team: experts who work with a customer during a live attack.
  • Professional Services: paid installation and set-up.
  • Recovery warranty: up to $10 million on the top plan, with conditions.
  • UK Sovereign Cyber Recovery Cloud (March 2026): a rebuild space kept entirely inside the UK, run with Rackspace.
  • Rubrik Zero Labs: a research team whose attack data also feeds the sales pitch.

3Business model and revenue engine

How money is made on one deal

A customer signs a contract, usually for three years, for the right to use the software. Three levers set the price.

  • Volume. For servers and files, the amount of data protected. For apps like Microsoft 365, the number of users.
  • Plan. Three tiers: Foundation, Business and Enterprise. Higher tiers unlock the attack-recovery tools and the warranty.
  • Add-ons. Identity, cloud, online-app and AI-agent products.

Prices are not published. Every deal is quoted and discounted. Outside price lists suggest about $130 to $230 per terabyte per month before discounts. Treat that as a rough guide.

Where the profit comes from

Software is expensive to build and cheap to copy. Once it exists, each extra customer mostly adds revenue. The main running costs are staff, cloud hosting bills, and the margin given to partners.

The single highest earner

Subscriptions to Rubrik Security Cloud for protecting large companies' data. Of $1.66 billion in yearly subscription value, $1.48 billion is for cloud-delivered products. Identity and AI agents are growing quickly from a small base.

The growth mechanics

  • Subscription ARR (annual recurring revenue) is the yearly value of all live subscriptions. It is the number investors watch. $1.66 billion at July 2026, up 33%.
  • Land and expand: win a customer with one product, then sell more. Nearly half of the 2,000 customers in Europe, the Middle East and Africa use three or more products.
  • Data grows by itself. Customers store more every year, so a deal priced on volume tends to rise at renewal.
  • Moving up the tiers. A customer who starts on Foundation can be upgraded once the security team gets involved.

Who the money passes through

Rubrik rarely bills the customer directly. It sells through partners: resellers, distributors, consulting firms, and the online stores run by Amazon, Microsoft and Google.

Why use partners? They already hold the customer relationship and a place on approved-supplier lists. Rubrik reaches thousands of buyers without hiring a salesperson for each.

Is it profitable?

  • In cash: yes. It took in $65.7 million more than it spent last quarter. It forecasts $323m to $333m for the year.
  • In official accounting profit: no. It reported a $61.8 million loss last quarter. Much of the gap is staff pay given in shares, which uses no cash.
  • Cushion: $1.75 billion in cash and short-term investments.

4Target audience and customer psychology

The exact customers

Large organisations for whom being offline is very expensive or dangerous. Rubrik had over 6,000 customers when it listed in 2024.

  • Banks and insurers: regulators set limits on how long key services may be down.
  • Hospitals and health bodies: downtime can harm patients. UK example: Northumbria Healthcare NHS Trust.
  • Government and councils: UK example: Brent Council.
  • Retailers and manufacturers: every hour offline is lost sales or a stopped production line.

Why Rubrik targets them

  • Large data volumes mean large contracts, since price follows volume.
  • Strict rules mean they must prove they can recover, not just claim it.
  • Complex estates mean many systems, so more products to add later.
  • They can pay a premium for lower risk.

The pain that forces a purchase

Ransomware is software that scrambles a company's systems until money is paid. The downtime usually costs far more than the ransom.

  • Marks & Spencer (2025): around £300 million off profit, with online orders stopped for weeks.
  • Jaguar Land Rover (2025): production halted. The UK's Cyber Monitoring Centre estimated a £1.9 billion cost to the UK economy.
  • Synnovis (2024): an attack on an NHS blood-testing supplier postponed thousands of London appointments.

The psychology behind the decision

  • It is personal. After a major attack, named executives answer to the board, to regulators and sometimes to the press.
  • "Could that be us?" A high-profile attack on a peer turns a vague worry into a board question with a deadline.
  • Untested confidence. Most firms have backups. Few have ever rebuilt everything from them. The gap between the two is where Rubrik sells.
  • Outside pressure. Regulators want evidence. Cyber insurers ask about backup protection before offering cover.
  • Fear of slowing down. With AI agents, the worry is the opposite: saying no and falling behind competitors.

What makes the price worth it

Rubrik is usually one of the dearer options. The case rests on simple arithmetic: hundreds of thousands of pounds a year against tens of millions per week offline.

  • Time. Days to recover instead of weeks.
  • Certainty. Knowing which copy is clean before restoring it.
  • Fewer tools. One product replaces several older ones.
  • Evidence. Recovery tests and reports to show regulators and insurers.
  • The warranty. Money behind the promise.
Three objections a Sales Engineer hears, and the honest replies

"We already have backup." Reply: can it be deleted by one stolen login, and have you ever rebuilt from it?

"Our cloud provider covers this." Reply: providers keep the service running. Protecting what you put in it is your job.

"It costs too much." Reply: compared with what? Price one week offline first.

5History, scale and internal structure

When, why and by whom

Rubrik was founded in January 2014 in Palo Alto, California, by Bipul Sinha, Arvind Jain, Soham Mazumdar and Arvind Nithrakashyap.

Sinha had been an investor at Lightspeed, which became the first backer. The founders saw that backup was old, fiddly and stitched together from many parts. Their answer was one box that could be set up in under an hour.

The turning point was around 2020 to 2022. Ransomware surged, and Rubrik repositioned from backup to security. It also switched from selling boxes to selling subscriptions.

8Commercial awareness and industry forces

Opportunities

  • Attackers log in, they do not break in. Groups such as Scattered Spider talk help desks into resetting passwords. That moves spending toward login recovery.
  • AI agents are outrunning the controls. Rubrik's survey found only 23% of IT leaders can see every agent in their organisation, and 86% expect agents to outpace safety controls within a year.
  • Regulators want evidence. See the box below.
  • Supplier consolidation. Tight budgets favour one product doing four jobs.
  • The VMware shake-up. After Broadcom bought VMware and raised prices, many firms are moving systems elsewhere. A move is a natural moment to rethink backup.
  • Data sovereignty. More governments require data to stay in-country.
The rules worth knowing by name

DORA: an EU law for financial firms, in force since January 2025. It requires tested recovery plans.

NIS2: an EU law extending cyber duties to many more sectors.

UK Cyber Security and Resilience Bill: the UK's update. It was in its final House of Lords stages in late October 2026. Check whether it has become law.

Bank of England resilience rules: since March 2025, UK banks must stay inside a stated maximum downtime for key services.

Threats

  • Everyone is converging. Veeam bought Securiti. Cohesity absorbed Veritas. Commvault sells login recovery. Rubrik's lead is narrowing.
  • Security giants. CrowdStrike, Palo Alto Networks and Microsoft want the AI agent safety market, and already own the customer relationships.
  • "Good enough" from cloud providers. Basic backup comes cheap or free with the cloud.
  • A cooling AI market. If AI spending slows, the Agent Cloud bet pays off later.
  • A demanding share price. It assumes fast growth continues. One weak quarter would be punished.
  • Economic pressure. When budgets tighten, three-year premium contracts get harder scrutiny.

How Rubrik is adapting

  • Widening what "recovery" means, from data to logins to AI actions, to stay out of a price war over backup.
  • Partnering with would-be rivals. Its findings feed into CrowdStrike and Microsoft tools, so it is seen as a complement.
  • Buying specialists to enter new areas quickly.
  • Investing locally in the UK to meet in-country rules and sit close to regulated buyers.
Three opinions you could voice in an interview

One. The risky part of the AI bet is timing. Rubrik must sell agent safety before the security giants bundle it in for free.

Two. Identity may matter more than AI for the next two years, because it solves a problem customers already have budget for.

Three. Choosing London over an EU capital is a statement about UK regulated industries, and about where the customers already are.

9The application question: technical answer ideas

The question

"Pick one Rubrik product or capability. Who would you pitch it to, and what's the first question you'd ask them?"

What is really being tested

The advert says Rubrik's SEs "shape the required capabilities a deal comes down to". In practice that means asking a question that makes the customer add a new requirement to their list, one Rubrik happens to meet.

So the first question is the answer. The product is only the set-up for it.

What most applicants will write

"Rubrik Security Cloud, to a security chief, asking how confident they are about ransomware." That names the whole company, the obvious buyer, and a question about feelings. Anyone can write it without knowing the product.

The recipe

  • One narrow capability. A named feature, not a platform.
  • One specific person. Job title, industry, and why they care this month.
  • One question with a factual answer. A number, a name, a place. Something they must go and check.
  • One line on what the answer tells you.
  • One honest limit. It shows you read past the brochure.

Idea 1 (top pick): Identity-First Recovery

Pitch to: the Head of Infrastructure at a UK retailer, in the year after Marks & Spencer.

"If every domain controller were encrypted tonight, what would your backup admins log in with?"

The trap it exposes: a domain controller is a server that runs the login system. Many backup tools check passwords against that same system. When it is down, the people meant to restore it cannot sign in.

Product depth to show:

  • Rubrik's control screen is hosted outside the customer's network, with its own sign-in.
  • It lifts only NTDS.dit and SYSVOL from the backup onto a freshly built Windows server. Anything hidden in the old operating system stays behind.
  • It strips out the records of other domain controllers by default, so the rebuilt one does not sync with infected machines.
  • Login-server backups are checked for attack fingerprints before one is marked clean.

Honest limit: the new server must run the same major Windows Server version as the old one.

The requirement it plants: "our recovery tool must be reachable when our login system is not".

Idea 2 (simplest question): Quorum Authorization

Pitch to: the Head of IT Audit at a UK building society.

"How many people here could delete every backup you hold, acting alone?"

The trap it exposes: the answer is a number, and the only safe number is zero. In most firms it is at least one. An attacker needs just that one login.

Product depth to show:

  • Backups are written to storage that only accepts additions.
  • Retention Lock stops the "keep for" period being shortened.
  • Quorum Authorization needs two named approvers before protected data is deleted or kept for less time.
  • A further copy can sit in Rubrik Cloud Vault, in an account Rubrik owns, with separate logins.

Why few will say it: the buyer is audit, not IT. And the question needs no technical knowledge to answer, which makes it land with a board.

The requirement it plants: "no single person can destroy our backups".

Idea 3 (best link to the AI project): Agent Rewind for Claude Code

Pitch to: the VP of Engineering at a software firm that has just given every developer an AI coding assistant.

"If a coding agent force-pushed over your main branch and deleted the others at 2am, what would you restore from that the agent's own access could not also have deleted?"

The trap it exposes: a force-push overwrites shared code history. The usual undo sits in the same place as the damage, under the same permissions the agent used.

Product depth to show:

  • Unchangeable copies of GitHub and Azure DevOps are kept outside the code store.
  • The files that steer the assistant (CLAUDE.md, settings, tool permissions) are version-tracked, and unexpected changes are flagged.
  • Each agent's inputs, tool use and chain of instructions are recorded, so one bad change can be traced and reversed alone.

Honest limit: it can only rewind agents whose actions it is able to observe.

The requirement it plants: "our undo must live somewhere our agents cannot reach".

Idea 4: Anomaly Detection as a second alarm

Pitch to: the manager of the security monitoring team at a manufacturer.

"If an attacker switched off the security software on a server before scrambling it, what would tell you it had happened?"

The trap it exposes: attackers routinely disable security tools first. Most firms have no second source of truth.

Product depth to show: after each backup, a small description of what changed goes to Rubrik's hosted service. Check one compares it with that system's normal pattern. Check two looks for the jump in randomness that scrambling causes.

Honest limit: a rival argues very slow, partial scrambling can stay under the alarm level.

Why few will say it: it pitches a backup product to the monitoring team, as an alarm.

Idea 5: Turbo Threat Hunting

Pitch to: the Head of Operational Resilience at a UK bank.

"In your last recovery test, how much of the clock went on restoring data, and how much on deciding which backup you could trust?"

Product depth to show: the usual method opens and scans each backup in turn. Rubrik fingerprints every file when the backup is taken, so the hunt is an index lookup. Results are written onto each backup's record and infected ones quarantined.

The line to use: "Recovery is a search problem before it is a storage problem."

Idea 6: Okta recovery

Pitch to: the Head of IT at a fast-growing online business that runs everything through Okta and has no Active Directory.

"If an administrator's access were misused this afternoon to delete your sign-in rules and groups, what would you restore them from?"

Product depth to show: restores users, groups, apps and rules into the live account. Brings back what a restored user depends on in the same step. Slows itself to stay inside Okta's request limits. Can restore into a separate clean account.

Why few will say it: it targets a firm that believes it has nothing to back up because "it is all in the cloud".

Idea 7: Agent Identity

Pitch to: the Head of Identity at an insurer already using Okta or Microsoft Entra.

"How many of your AI agents are holding a key right now that never expires?"

Product depth to show: every action passes three checks. The last issues a pass valid for that single action. It uses the firm's existing Okta or Entra set-up.

Watch out: Rubrik has not said clearly whether this is on full sale.

Idea 8: UK Sovereign Cyber Recovery Cloud

Pitch to: the technology chief of an NHS trust.

"If you had to rebuild your patient record system after an attack, where would you rebuild it while investigators still have your data centre sealed off?"

Product depth to show: an isolated rebuild space inside UK borders, run with Rackspace since March 2026, switched on only during a recovery.

Why few will say it: a UK-only service, for a London role, that most applicants will not know exists.
